## 1. 裁决

1. **BGE-M3 评测阶段关闭**，结论保留 `INCONCLUSIVE`。
2. **不替换 BGE V1**；BGE-small 继续作为稳定基线。
3. **不下载 BGE-M3 HF 权重，不新建 FlagEmbedding 环境，不继续 ColBERT/reranker 优化。**
4. **不新立** `EULER-SEMANTIC-RETRIEVAL-BGE-M3-FULL-CAPABILITY-01`。
5. 已有 BGE-M3 / BM25 / hybrid / reranker 的实验代码、数据和报告作为技术研究资产保留。
6. 后续产品接入只做必要集成：
   - 保留 BGE V1；
   - 增加 BM25 独立候选召回；
   - 简单、可解释的融合；
   - 题目结构/来源证据排序；
   - 整页照片返回候选，用户明确选择；
   - Unknown 走 Session 临时解析，不直接进入 QCore。

## 2. 规模判断

| 项 | 目标规模 | 工程含义 |
|---|---|---|
| QCore | 10 万级 Question | 单机检索可承受，不是分布式检索场景 |
| 用户 | 1–3 名学生（家庭内部） | 无大规模并发压力 |
| 拍照题 | 数百至上千张，按请求处理 | 照片不等于 QCore 资产，不默认永久入索引 |
| 检索目标 | 找到对应题；找不到则即时解析 | 不需要通用搜索平台 |

10 万题 × 1024 维 FP32 约 **410MB** 原始向量；即使加索引、元数据和冗余，也远低于需要复杂分布式/多向量架构的规模。**单机 + 普通向量索引 + BM25 足够。**

---

## 3. 为什么停止

- 十万题不是“海量文档”，不需要 ColBERT 全量索引、分布式向量服务或多级检索集群；
- 用户照片是**一次检索请求的输入**，不是永久 QCore 资产；
- 真实数据已证明：BM25 是强信号；BGE-M3 dense 未超过 gemma/BGE；reranker 当前部署不可用；
- 继续模型军备竞赛的边际产品价值低，且挤占教学闭环开发；
- 当前最大风险是“检索系统研究了很多，学生还没用上完整家教闭环”。

---

## 5. 下一步产品优先级

1. 跑通学生学习闭环：拍照/输入 → 检索 → Exact 确认 → TeachingScript → Interactive Lesson → 追问 → 记录；
2. 提高检索可靠性：整页多题分段、候选展示、用户选择、错误防护、Unknown 降级、照片与 QCore 资产分离；
3. 学习分析：练习记录、错题/知识点、薄弱点、复习策略；
4. 只有在真实检索失败样本证明现有 Top-K 不足时，再评估 embedding/reranker 升级。

---

## 6. 冻结边界

- 不改生产 QCore；
- 不切换生产默认模型；
- 不新增模型服务依赖；
- 不因“未来十万题”提前建设分布式/多向量检索；
- 不把用户照片默认写入 QCore 或永久索引。
